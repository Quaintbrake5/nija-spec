## 0. Confirmed Tech Stack

- **Core Engine (CLI):** Node.js / TypeScript
- **LLM Providers:** 
  - Primary: Gemini 2.5 Flash (Cloud)
  - Fallback/Local: Gemma 4 31B IT
- **Generator Architecture:** Deterministic Template Pattern (Language-agnostic)
- **Infrastructure (Optional v1+):** FastAPI (Python), React + Vite + CSS3, PostgreSQL, Redis, S3-compatible Storage
- **Target Frameworks:** 
  - JS/TS (Jest), Python (Pytest), Go (testing), Java (JUnit), C# (xUnit), PHP (PHPUnit)

## 1. Architectural Evolution: The Generator Pattern
To support multiple languages while maintaining the "Trust Engine" (Reasoning $\rightarrow$ Deterministic Compilation) principle, we will implement a **Generator Pattern**.

### Current Flow:
`Markdown Spec` $\rightarrow$ `Gemini (JSON)` $\rightarrow$ `JS Template` $\rightarrow$ `Jest Tests`

### New Flow:
`Markdown Spec` $\rightarrow$ `Gemini (JSON)` $\rightarrow$ `Language-Specific Generator` $\rightarrow$ `Language-Specific Tests`

### Key Changes:
- **Phase 1 (Cloud Reasoning):** Remains largely unchanged. The JSON schema will focus on *semantic intent* (e.g., "Route X should return 200") rather than language-specific syntax.
- **Phase 2 (Local Generation):** Replace the hardcoded JS template with a `Generator` interface.
  - Each supported language/framework will have its own `Generator` implementation.
  - The CLI will accept a `--lang` or `--framework` flag (e.g., `nijaspec generate --lang go`).

## 3. Verification Strategy
- **Golden File Tests**: Maintain snapshots of generated tests for *each* language given the same input spec.
- **Cross-Language Determinism**: Verify that the same semantic JSON produces the logically equivalent test in different languages.
- **Syntax Validation**: Use language-specific linters/parsers in the `verify` step to ensure the generated code is syntactically correct.

## 4. Risk Assessment
- **Template Bloat**: Managing templates for 10+ languages can become complex.
- **Mitigation**: Use a structured templating engine (like Handlebars or a custom DSL) instead of raw template literals for complex languages.
- **Framework Fragmentation**: A language like Java has many test frameworks (JUnit 4, 5, TestNG).
- **Mitigation**: Standardize on one "Gold Standard" framework per language for the MVP.
